# ADR-004: ユーザー文字列の照合はOCR誤認を許容する形で行う

- ステータス: 承認済み
- 日付: 2026-07-17

## 文脈

ダミー文書の実機検証で、OCRがカタカナ「ベ」をひらがな「べ」と読んだ
結果、「株式会社ベータ電機」の置換ルールがマッチせず、しかも監査も
同じOCRを見るため残存を検出できない（置換と監査が同時にすり抜ける
対称的盲点）ことを確認した。ほかに全字間スペース、ハイフンの長音記号化
（045-…→045ー…）、URLのコロン欠落も実測した。

## 決定

検索・辞書・ポリシーtextルール・監査禁止語が共有する照合経路
（menreiki-detectの `RegexRule::literal`）で、次のOCR揺れを許容する。

- 文字間の任意個の空白（CJKは1文字ずつ単語化されるため）
- ひらがな⇔カタカナの同形字
- ダッシュ類似字（- ‐ ‑ – — − ー）の相互置換

組み込みパターン（電話・郵便番号・URL）も同じ揺れを受ける。数字や
英字が別の文字に化ける誤認（192.168…→192ユ68…）は照合では救えず、
複数OCR併用・VLM補助・人間レビュー（PRD §26.1）の領域とする。

## 帰結

- 置換と監査が同一の頑健照合を使うため、片方だけすり抜ける事故が
  起きない
- 許容範囲が広がる分の誤マッチは、候補として人間が棄却する前提の
  設計（PRD §26.5）に吸収させる
