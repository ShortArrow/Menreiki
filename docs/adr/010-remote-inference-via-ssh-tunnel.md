# ADR-010: リモート推論はSSHトンネルで接続し、TLSは強制しない

- ステータス: 承認済み
- 日付: 2026-07-19

## 文脈

推論をリモートのGPUマシン（NVIDIA DGX Spark等）で動かしたい場合がある。
推論クライアントはlocalhost限定であり、接続手段が問題になった。
検討した選択肢:

- hostsファイルでlocalhost相当の名前をリモートIPへ向ける: 現代の
  Windowsはlocalhostの名前解決を特別扱いするためほぼ機能せず、仮に
  機能しても「アプリはローカルと信じたまま原文が平文でLANへ出る」
  状態になり、localhost制限が守る保証を静かに壊す
- クライアントをhttps必須にする: loopback通信はマシンから出ないため
  TLSで守る区間が存在しない。一方でOllama・LM Studio・llama.cpp server
  は既定で平文HTTPを提供するため、全ランタイムで自己署名証明書の
  セットアップを強いることになり、検証無効化という悪い習慣を招く
- リモートエンドポイントの直接許可: 「構造的に外部送信できない」と
  いう単純で監査しやすい保証を失う

## 決定

- 推論クライアントのlocalhost限定は維持し、TLSの強制は行わない
- リモートGPUで推論する場合はSSHポートフォワード
  （`ssh -N -L 11434:localhost:11434 user@gpu-server`）で接続する。
  アプリから見た接続先はloopbackのままなのでコード上の保証が保たれ、
  原文は暗号化されたトンネル内のみを通り、どのマシンへ送るかが
  トンネルを張るという明示的な操作で可視化される
- hostsの書き換えと平文のポート転送は案内しない

## 帰結

- コード変更ゼロで、リモート推論の要求を満たせる
- 将来、信頼済みリモートエンドポイントの直接許可が必要になった場合は
  新しいADRで決定し、その際は非loopback接続へのTLS必須化と
  プライベートアドレス帯の検証を条件に含める
