# ADR-011: 当面は日本語文書に集中し、ドキュメントは言語タグ付きファイル名にする

- ステータス: 承認済み（UI翻訳の見送りはADR-018により置換）
- 日付: 2026-07-19

## 文脈

海外利用に向けたi18nの是非を検討した。i18nには3つの層がある:
UI言語の翻訳（文字列は少なく機械的）、文書言語ごとの検出パック
（法人格・敬称・住所・電話などの言語固有ヒューリスティックの設計と、
その言語の実文書での検証が必要で、コストの大半を占める）、
法規制と文化（Menreikiは法的な匿名化を保証しない立場を取っており、
docs/PRD.jp.md §5・§28.4の構図はGDPR圏でもそのまま成立するため、
実はブロッカーではない）。

現在はベータ段階で、検証相手は日本語ユーザーであり、製品の差別化は
日本語文書の扱いの強さ（かな同形字、法人格、OCRの日本語癖）にある。

## 決定

- i18n（UI翻訳・多言語検出パック）は当面見送る。再検討のトリガーは
  日本語ベータのフィードバック一巡、または英語文書の利用者の出現
- 扉を開けておくための作法として次の2点を守る:
  - 検出の言語固有知識はmenreiki-detectに隔離し、coreや他の層へ
    染み出させない（将来の言語別ルールパック分割を小改修に保つ)
  - docs/配下の日本語ドキュメントはファイル名に言語タグを付けて
    `*.jp.md` とする（PRD.jp.mdと同じ規約）。将来の英語版は同名の
    `*.md` または `*.en.md` として併存できる。ADR-000のファイル名
    規約 `NNN-短いケバブケース.md` はこの規約で読み替える

## 帰結

- 既存のADRファイルは `*.jp.md` へ改名した
- UI文字列のi18nフレームワーク導入は、必要になった時点で行う
