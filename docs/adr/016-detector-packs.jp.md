# ADR-016: 検出パックはデータのみの配布形式とする

- ステータス: 承認済み
- 日付: 2026-07-27

## 文脈

業種別の検出内容（型番パターン・業界用語・組織名）を、コア本体とは
別に配布・追加できる拡張点が欲しい。将来の収益化（オープンコア）の
候補単位でもある。Rust のネイティブプラグイン（dll）は ABI が不安定で
保守負担が大きく、任意コードの実行はローカルファースト方針の信頼
モデルを壊す。

## 決定

検出パックは**コードを含まない、データのみのJSONファイル**
（`*.mnrkpack.json`）とする。

1. **内容は2種類だけ** — 正規表現ルール（category＋pattern）と、
   OCR揺らぎ耐性で照合するリテラル語（category＋text）。読み込みは
   既存の `RegexRule` / `literal_rule` へ変換するだけで、実行機構を
   一切追加しない。
2. **検証してから受け入れる** — 取り込み時に `parse_pack` が
   スラッグ名・必須項目・全パターンのコンパイル可否を検証し、
   不正なパックは拒否する。
3. **保管はアプリ全体、名前空間は detector 属性** — パックは設定
   ディレクトリの `packs/` に置かれ、全プロジェクトの解析に参加する。
   由来は finding の detector（`pack:<name>`）で常に追跡できる。
4. **署名フィールドは予約のみ** — `signature` は形式に含めるが、
   検証は署名付き配布（有償パック）を始める段階で実装する。
   検証には配布者の公開鍵（トラストルート）が必要で、それ無しの
   署名検証は意味を持たないため。

## 帰結

- パックは監査可能（中身を読めばすべて分かる）で、サンドボックスが
  不要。データのみなのでライセンス・安全性の議論もコアと分離できる。
- プロジェクト単位の有効/無効切り替えと、CLI での読み込みは
  将来課題（現状はデスクトップアプリのみ・インストール即全体有効）。
- 形式の仕様と例は docs/DETECTOR-PACKS.jp.md に置く。
