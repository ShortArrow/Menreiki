# ADR-018: UIを日英二言語にし、既定はOS言語に従う

- ステータス: 承認済み
- 日付: 2026-07-31

## 文脈

ADR-011は「i18n（UI翻訳・多言語検出パック）は当面見送る」とし、再検討の
トリガーを「日本語ベータのフィードバック一巡、または英語文書の利用者の
出現」に置いた。

トリガーは想定と別の経路で満たされた。Microsoft Storeの審査担当者は英語
環境から製品を評価する。日本語のみのUIでは、審査担当者が主要機能へ到達
できたかを自力で判断できず、10.3.3 "App Is Testable" の差し戻しが続いた。
配布経路そのものが「英語UIを必要とする利用者」であり、日本語ベータの
フィードバックを待つ前提が成立しない。

ADR-011が挙げたi18nの3層のうち、コストの大半は検出パック（法人格・敬称・
住所などの言語固有ヒューリスティックの設計と実文書での検証）にある。UI
文字列の翻訳はそれとは独立で、機械的に完了する。

## 決定

- **UI文字列のみを二言語（日本語・英語）にする。** 検出パックは日本語の
  ままとし、製品の対象は日本語文書という位置づけを変えない。
- **辞書は自前で持つ。** `apps/desktop/src/i18n.tsx` に日本語辞書を正とし、
  英語辞書を `Record<keyof typeof ja, string>` として型で縛る。翻訳漏れは
  ビルドエラーになる。i18nライブラリは導入しない（依存を増やさず、必要な
  のはキー参照と `{name}` の補間だけ）。
- **プロース主体の画面はロケール別コンポーネントで並置する。** ヘルプ
  （`HelpJa` / `HelpEn`）と初回通知は、インライン強調と図を含む長文であり、
  断片の辞書に割ると原文の可読性が失われる。短いラベルは辞書、長文は
  コンポーネントという境界にする。
- **言語は `config.toml` の `ui_language`（`auto` / `ja` / `en`）で決まる。**
  既定の `auto` はOS言語に従い、日本語環境は日本語、それ以外は英語。設定
  ダイアログの言語ピッカーで明示指定に上書きできる。
- **MSIXマニフェストは `ja-JP` と `en-US` の両方を宣言する。**

## 帰結

- 英語環境の利用者と審査担当者は、設定を触らずに英語UIを得る。日本語環境
  の表示は変わらない。
- UIに新しい文字列を足すときは日本語辞書と英語辞書の両方を書く。片方だけ
  ではコンパイルが通らない。
- E2Eは表示言語に依存するため、各specは `config.toml` に `ui_language` を
  書いて言語を固定する。英語表示は専用specで検証する。
- 検出パックの多言語化は未着手のまま。英語文書の検出品質を求める要望が
  出た時点で、あらためて判断する。
