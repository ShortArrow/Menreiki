# ADR-019: 辞書をプロジェクト層とユーザー層の二層にし、複製で受け渡す

- ステータス: 承認済み
- 日付: 2026-09-11

## 文脈

利用者が育てる語彙は3種類あり、いずれもプロジェクトに閉じている。

| 辞書 | 中身 | 置き場所 |
|---|---|---|
| 検出語 | 以後の解析で必ず候補にする語（分類＋語） | `rules/dictionary.json` |
| 無視リスト | 候補にしない語（分類つき） | `project.mnrk` の `settings.ignored` |
| Entity台帳 | 表記ゆれの集合と、置換先の別名 | `entities/entities.json` |

同じ取引先を扱う案件が続くと、これらを毎回作り直すことになる。アプリ
層（ADR-014）にあるのは検出パック（ADR-016）だけで、取り込み専用の
配布物であり、利用者が自分の語彙を置く場所ではない。

同時に、「〜装置」「〜カンパニー」のように接尾辞で決まる名前を利用者
自身が足したいという要望がある。カンパニーなどの法人的接尾辞は組み込み
ヒューリスティックが拾うが、「装置」は 本装置／検査装置 のような一般
名詞にも当たるため、既定検出器に入れると工業系文書で候補が溢れる。
業種ごとの接尾辞は利用者の辞書に属する。

検討した選択肢:

- ユーザー辞書を実行時に参照する: 別名を後から変えた瞬間に、過去案件の
  出力と監査結果（ADR-015）が再現できなくなる。`project.mnrk` は文書と
  一緒に持ち運ぶ設計（ADR-014）なので、別マシンで開くと辞書が無く
  同じ問題が起きる
- 検出パック形式にEntity別名を載せる: パックは配布物、別名は個人の運用
  であり、混ぜると本体・有償コンテンツの境界（ADR-017）が曖昧になる
- 「グローバルを打ち消す」否定エントリを持つ: 2層の合成規則が双方向に
  なり、どちらが効いているかを読者が追えなくなる

## 決定

1. **ユーザー辞書をアプリ層に置く。** `~/.config/menreiki/dictionary.json`
   に、プロジェクト辞書と同じ3種（検出語・無視リスト・Entity台帳）を持つ。
2. **受け渡しは複製のみ、実行時参照はしない。** プロジェクト作成時に
   ユーザー辞書をプロジェクトへ複製する。レビュー画面の「昇格」操作で
   プロジェクトの項目をユーザー辞書へ複製する。ユーザー辞書を後から
   変えても既存プロジェクトには影響しない。解析・置換・監査が読むのは
   常にプロジェクト内のファイルだけで、この点は現状と変わらない。
3. **衝突はインポート時にだけ起き、既存が勝つ。** 実行時に2層を合成
   しないため、同じ語が両層で食い違っても解析には影響しない。複製
   （プロジェクト作成・昇格・インポートのマージ）で同一キーの項目が
   ぶつかったときは受け側の既存項目を保持し、無い項目だけ追加する。
   否定エントリは作らない。
4. **検出語に接尾辞種別を足す。** 辞書の検出語は「語」「接尾辞」
   「正規表現」の3種とする。接尾辞は `suffix_rule(category, suffix)` が
   組み込みヒューリスティックと同じ字間スペース耐性の正規表現に展開する
   ので、利用者は正規表現を書かない。正規表現は取り込み時にコンパイル
   検証し、壊れたものは受け付けない（パックと同じ扱い）。
5. **Entity別名は検出パック形式に入れない。** パックは配布用の検出
   内容（正規表現ルール・語）のまま据え置く。
6. **辞書は層ごとにエクスポート・インポートできる。** 交換形式は
   `*.mnrkdict.json` の1ファイルで、検出語（語・接尾辞・正規表現）・
   無視リスト・Entity台帳の全セクションを束ねる。ユーザー辞書の保存
   形式もこれと同一にする。プロジェクト側は既存3ファイルの配置を変えず、
   エクスポート時に束ね、インポート時に振り分ける。インポートでは
   「マージ（既存を保持し不足分を追加）」か「置換（全入れ替え）」を選ぶ。

## 帰結

- 過去案件はプロジェクトフォルダだけで再現でき、辞書の後変更に左右
  されない。別マシンへ持ち出しても辞書ごと移動する
- 案件をまたぐ語彙はユーザー辞書に昇格して蓄え、新規案件は作成時点の
  ユーザー辞書を初期値として始まる。ユーザー辞書の更新を既存案件へ
  反映したいときは、エクスポートしてマージでインポートする
- 検出パックの形式と信頼モデルは変わらない。パックは「配布される
  検出内容」、辞書は「利用者の運用」という境界が保たれる
- 実装順は、接尾辞種別（`suffix_rule` と辞書項目の種別）、ユーザー辞書
  ファイルと作成時複製、昇格操作、エクスポート／インポートの順で、
  それぞれ独立に検証できる
- 交換形式の仕様は docs/DETECTOR-PACKS.jp.md と同様の現在形文書に置く
  （実装時に作成する）
